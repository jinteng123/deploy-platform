# CI/CD 平台故障与发布恢复手册

本文供平台不可用、发布任务中断或外部写入结果不明时使用。它描述当前代码支持的检查与恢复边界；不替代组织的生产变更、值班升级和 Kubernetes 应急制度。现场恢复仍需由有权限的 operator/admin 执行并留痕。

## 运行边界

- Helm 当前强制 `replicaCount=1`，且使用 `Recreate` 更新策略。不要通过扩成两个 Pod 临时提高可用性；多副本 Worker/Store 协调尚未完成。
- `/health/live`（兼容路径 `/health`）只检查进程是否能响应。`/health/ready` 会在最多 2 秒内检查 MySQL；MySQL 不可达时返回 503，Kubernetes Service 会停止把平台请求发给该 Pod。就绪探针不检查 Kubernetes API、云效或网关。
- 平台故障本身不会改写业务 Service selector 或工作负载。现有业务流量是否正常仍由业务 Pod、Service、Ingress/网关及其依赖决定；平台暂时不可用时，平台内新建/审批/恢复操作可能无法进行。
- 登录、发布状态、审批和恢复记录保存在 MySQL。恢复数据库备份时，必须同时恢复与这些集群凭据密文匹配的原 `CREDENTIAL_ENCRYPTION_KEY`；更换密钥不会自动重新加密历史数据。密钥只从现有秘密管理系统恢复，不能写入工单或本手册。
- Yunxiao 配置流水线的实际写入范围仍未确认。绑定、名称搜索、只读定义分析和人工结论记录均不会运行流水线。未完成完整定义、引用模板/脚本、执行身份和目标资源核对前，不要把它当作配置恢复手段，也不要假设它只写 ConfigMap/Secret。

## 平台不可用时

1. 记录首次发现时间、平台地址、报错和当前操作。通过现有集群监控/运维入口检查平台 Pod、事件和日志；不要在用户工单或聊天中粘贴数据库 DSN、API token、云效 PAT、Secret 内容或加密密钥。
2. 检查 `/health/live` 和 `/health/ready`：
   - liveness 非 200：进程未能响应，按组织的服务故障流程检查容器退出、启动日志和最近变更。
   - liveness 为 200、readiness 为 503：优先检查 MySQL 可达性和服务账号/网络策略。进程仍存活不表示平台可以处理请求。
   - 两者均为 200：基础进程与 MySQL 检查通过；继续检查浏览器/反向代理、Kubernetes API 访问、云效连接或具体网关，而不要据此推断这些依赖正常。
3. 检查已有业务入口和工作负载的实际状态，确认受影响范围。平台 Pod 不 Ready 不会自动把已有业务 Deployment 回滚或切镜像；不要仅凭平台页面离线推断业务中断，也不要只凭业务仍有流量推断平台恢复。
4. 使用组织批准的方式恢复平台进程或 MySQL。升级已有数据库时只应用所需的顺序迁移；不要在事故中回放完整迁移集或对线上数据运行未经审核的 DDL。若数据库由备份恢复，先验证 schema 与凭据解密密钥，再恢复平台流量。
5. 确认 `/health/ready` 返回 200、登录和只读页面可用后，再进入发布核对。健康检查通过不是未决发布已经安全的证据。

## 发布任务中断或写入结果未知

外部请求可能已经由 Kubernetes 接受，但平台未收到响应或未能保存回读结果。失败、中断、浏览器超时和重启都不能证明集群未改变。先读取事实，不要重复提交原发布或直接执行镜像写入。

1. 用平台页面读取任务详情；需要 API 时，使用登录会话和已有授权只读读取：
   - `GET /api/v1/deploy/logs/{id}`：任务状态、当前步骤、目标镜像和错误摘要。
   - `GET /api/v1/deploy/logs/{id}/actions`：持久化的外部动作意图/回读状态。
   - `GET /api/v1/delivery-runs/by-deploy-log/{id}`，或已知运行 ID 时 `GET /api/v1/delivery-runs/{id}`：蓝绿/金丝雀运行、阶段、事件和动作。
2. 通过平台只读资源页或组织批准的集群只读入口，核对目标集群、namespace、Deployment UID、容器镜像、Service selector、候选资源与 EndpointSlice。把看到的时间和资源身份记入事故记录；若无法确认读到的是同一个 UID/入口，停止恢复并升级给集群负责人。
3. 根据发布类型选择受支持的恢复入口：

| 场景 | 可执行的核对/恢复 | 停止条件 |
|---|---|---|
| 滚动镜像任务为 `interrupted` | operator 可调用 `POST /api/v1/deploy/logs/{id}/reconcile`。服务端回读当前镜像；只有它与该任务持久化的审批目标完全相同，才恢复 rollout 检查。 | 若仍是旧镜像，平台不会重放写入；按页面提示重新生成发布计划。若是第三种镜像、UID/目标不匹配或回读失败，保持中断并升级处理。 |
| 蓝绿任务存在未决动作或 `needs_attention` | 先读取运行和动作，再由 operator 使用运行页的“核对/恢复”入口（`reconcile`）。服务端重新检查稳定 Service、候选 Deployment、预览 Service、selector 与端点，已知结果后才续接。 | selector 指向未知轨道、候选身份不匹配、Service/EndpointSlice 无法回读时停止；不要重复切流或自行重建同名候选。 |
| 蓝绿生产流量需要回到稳定版本 | 仅在确认业务兼容性、稳定 Deployment 与绑定的 Service 身份后，使用运行页 `restore_stable`；该操作要求版本匹配并显式确认恢复兼容性。完成后再次核对 Service selector 和 EndpointSlice。 | 平台不能恢复 ConfigMap/Secret 历史值、数据库或外部路由。兼容性未知、稳定版本不健康或入口已被外部更改时，不要确认恢复，升级给应用/集群负责人。 |
| 候选资源清理 | 仅在保留期结束且运行页允许时使用 `cleanup_candidate`。平台按 UID、所有权标签、稳定绑定和入口回读检查后删除平台拥有的预览 Service 与候选 Deployment。 | 不手工删除资源来“解锁”。删除仍在终止、所有权不匹配或回读不明时保留现场并升级。 |
| 镜像漂移通知 | 打开「发布观测」，按通知提供的 cluster/app 与目标位置核对期望镜像、实际镜像、最近成功部署基线和观察来源；对照同期任务与集群变更记录，再联系应用负责人确认影响。 | 通知表示 Deployment 镜像字符串不同于成功发布基线，不代表 Pod digest、配置或业务一定异常。平台不会自动回滚；未知或外部紧急修改时保留现场，按批准的发布/修复流程处理。 |

4. 蓝绿 `restore_stable` 或取消需要在界面确认恢复兼容性；所有动作要求当前 `expected_version` 和新的幂等键。版本冲突时刷新运行详情，再判断下一步；不要沿用过期页面提交动作。
5. 所有写入结果未知时先回读，不盲目重试。不要用旧式发布入口、直接 `kubectl patch`、YAML 保存或手工改 Service selector 绕过计划、审批和资源锁。

## 平台恢复后的闭环

- 对照事故窗口中的平台任务、运行事件、动作记录与集群实况，确认目标镜像、活动 Deployment UID、入口 selector、EndpointSlice 和候选资源状态一致。
- 将在平台外按组织应急流程实施的每项变更补记到事故/变更记录，并由平台 operator 对照实况完成受支持的只读核对；不要把外部变更伪装成平台任务成功。
- 若 MySQL 从备份恢复，确认已有用户/角色、审批范围、会话和审计数据可读，且集群凭据使用正确的历史加密密钥可解密。迁移与数据异常交由数据库负责人处理。
- 对配置流水线，只在负责人提供完整执行链、目标资源/namespace、实际身份权限和与镜像发布执行器的写入边界后，才更新核对结论。当前仍未知时，保留未知，不触发它。

## 事故记录与升级

记录发现/恢复时间、操作者、影响环境、目标 cluster/namespace/应用、release/deploy-log/run ID、发布策略、计划目标 digest、观察到的镜像和资源 UID、Service selector/EndpointSlice、使用的恢复动作及其结果、业务验证依据、外部变更单号。不得记录 Secret 值、token、PAT、数据库密码、完整 DSN 或加密密钥。

遇到无法确认的写入结果、资源身份变化、入口漂移、数据库 schema 不匹配、凭据无法解密或超出本手册恢复范围时，保留平台/集群现场和资源锁，按既有值班流程联系平台、数据库、集群或应用负责人。不要为了清除告警而删除锁、候选资源或任务记录。

## 当前仍需现场演练

本地自动化已覆盖单副本应用、MySQL 停启、Kind 蓝绿流程及若干 Kubernetes 写入响应丢失后的重启核对；这些测试不代表生产 HA 故障切换、真实网络/RBAC/准入策略或用户操作演练已经通过。首次生产试点前，应在隔离非测试环境验证本手册中的发现、数据库恢复、未决发布回读、恢复与升级路径，并记录实际值班联系人和组织规定的恢复时限；本仓库没有定义可直接复用的 SLO 或告警阈值。
