## 1. 视觉方向与信息层级

采用克制、清晰且精致的运维工作台：保留现有深蓝侧栏和浅色工作区，主要内容用中性背景、清晰标题、
少量状态色和稳定留白。页面要像同一产品的一部分，而不是一组拼起来的管理表单。通过排版、对齐、
分组和节奏建立视觉层级；避免卡片套卡片、重复边框、大面积渐变、彩色 KPI 卡、厚重阴影、过小文字，
也避免每行多个实心按钮制造噪声。借鉴 Octopus 的接入顺序、Spinnaker 的阶段视图，不照搬其页面密度。

每个页面先回答一个主问题：接入页“构建会更新哪里”；环境页“各环境跑什么”；计划页“本次改什么”；
进度页“现在在哪里、下一步是什么”；恢复页“能退到哪里、有什么影响”。主区展示可决策事实，
技术字段、完整 digest、原始 YAML 和日志放入可展开详情，不能隐藏阻断原因或影响范围。
全局布局、按钮、表格、状态徽标和间距一致，不能新增功能就引入一套局部色值。

## 2. 设计 tokens 与组件要求

复用 `frontend/src/styles/theme.css` 的 Shadcn/Tailwind 语义变量，并先建立共用页面组件。
当前侧栏为 `#173f7b`、浅色背景为 `#f2f5fb`、卡片为白色、基础圆角为 10px；这是兼容基础。
本期不另外换品牌色。若增加成功/警告/信息/未知 tokens，统一定义浅色与深色值并验证对比度，
不得在业务页面写临时 hex 色值。现有发布页局部硬编码背景/边框在改造时收敛到语义 tokens。

| 维度 | 规范 | 目的 |
|---|---|---|
| 间距 | 使用 4、8、12、16、24、32、48、64px；同类布局一致 | 页面外边距桌面 24/32，卡片 24，字段组 24，标签与输入 8 |
| 字号 | 页标题 24/30，区标题 18/20，正文/输入 14/16，辅助 12 | 关键目标不缩成辅助字号；正文行高约 1.5–1.7 |
| 字体 | 沿用项目字体，补系统中文 sans-serif；代码/镜像标识用等宽 | 中文、英文长名与数字都清晰，构建号/权重数字等宽对齐 |
| 色彩 | 中性表面为主，品牌色给选中与主行动；语义色只表达状态 | 成功绿色不用于所有部署卡；流量版本配色不暗示健康 |
| 层次 | 常态用细边框，弹层轻阴影；不要卡片内再嵌多层卡片 | 相邻信息靠留白与标题分组 |
| 圆角 | 沿用 radius-sm/md/lg，按钮、输入、卡片按组件统一 | 不在同页混用多种随意圆角 |
| 操作 | 一个决策区一个主行动，次要 outline/ghost，危险动作明确文字 | 行内高频操作最多一个，其余收入更多菜单 |
| 图标 | 沿用项目图标库，常用 16/20px，伴随明确文字 | 不以颜色或图标单独表达状态 |

共用组件拟包括：PageHeader、EnvironmentBadge、BindingSummary、CheckResult、VersionIdentity、
StageTimeline、TrafficSummary、ObservationFreshness、ActionBar、EmptyState。
名称是实现建议，验收关注统一行为与样式，不要求重复建设已有等价组件。

普通文字对比度至少 4.5:1，大字与必要非文字图形至少 3:1。深色模式独立核对灰阶、图表、状态色、
焦点与禁用态，不简单反色。表格长标识截断时提供可键盘访问的完整值与复制，不能只靠 hover。

## 3. 信息架构与页面职责

| 页面 | 主信息 | 主行动 | 次要内容 |
|---|---|---|---|
| 应用与组件 | 应用分组、镜像来源、环境绑定与接入状态 | 接入组件 | 搜索/过滤、编辑、Runner、技术详情 |
| 环境总览 | 各环境实际版本、制品验证、当前任务与更新时间 | 进入所选环境 | 集群/namespace/服务入口详情 |
| 发布计划 | 当前/候选对比、目标、策略、阶段、检查、恢复窗口 | 提交审批/开始非生产发布 | 技术影响预览、配置摘要 |
| 审批详情 | 完整计划、验证与恢复依据、申请人/基线 | 批准（有权限时） | 拒绝并说明原因、历史事件 |
| 发布现场 | 当前阶段、配置与实际流量、指标、下一步 | 当前服务端允许的动作 | 事件时间线、资源详情、日志 |
| 恢复确认 | 恢复目标、容量/健康、兼容性、入口影响 | 确认恢复 | 查看历史；不兼容时进入向前修复说明 |

发布观测区使用近 7/30/90 天选择器，指标卡统一浅边框与中性表面，不使用彩色 KPI 背板；每个 P95 和失败率都显示样本分母，窗口起止与最近观察时间就近可见。DORA 数据完整性放在可展开区域，逐项说明未知原因；单一应用与生产目标下的部署频率显示为“次数 / 统计天数”，跨目标或来源不完整时说明未知原因，没有成功部署时可明确显示 0。刷新保留既有数值并标出更新状态，统计窗口不随 15 秒自动刷新改变。

不再让组件列表承担所有配置和操作。桌面表格优先展示“组件、镜像仓库、环境摘要、接入状态”，
代码目录和 Kubernetes 三元组放行详情。各状态独立：镜像仓库待配置、代码来源未登记、部署目标
已绑定/无效、策略待配置、Runner 未接入/授权到期。明确登记的第三方镜像显示“第三方镜像”，
空代码地址不自动当作已确认的第三方来源；Runner 最近检查不能标成当前在线。
组件列表的接入说明按当前状态调整层级：无可用集群时先给集群设置行动，不展示无法执行的接入步骤；已有绑定时先让操作者看到实际组件、镜像仓库、业务归属与容器目标，说明卡只保留匹配规则，详细步骤可展开；首次接入且有可用集群时展示完整步骤。390px 已有绑定页面应在首屏看到至少一个组件的部署目标，而不是只有示例说明。历史数据即使已有绑定，只要业务关系仍标记待核对，主行动必须先进入该组件的环境核对；镜像仓库缺失时同屏保留独立的补全入口，避免把两项工作混成“增加部署目标”。浅色/深色视觉证据见[组件页面视觉核对](./visual-checks/components-mapping-390-light.png)。
旧绑定默认保留滚动策略，不因为未选择新策略就显示不能发布；“策略待配置”只用于明确未完成的
新配置草稿，蓝绿/金丝雀能力缺失另给原因。

## 4. 接入引导：有清楚的关系，也有舒服的阅读节奏

复杂接入用专页，组件详情中短编辑用抽屉。Runner 密钥/脚本配置保留安全要求，代码默认折叠，
避免脚本占满初始视口。标题与底部操作固定，内容区滚动；步骤变化回到内容顶部，保存输入。
不要让用户在长弹窗中寻找上一步或下一步。

```text
接入组件                         第 2 步 / 共 5 步
建立镜像与部署位置的对应关系

来源 ── 镜像与目标 ── 环境 ── 发布方式 ── 核对

┌ 主要配置区域 ─────────────────┐  ┌ 关系预览 ───────────────┐
│ 镜像仓库（例子 + 简短提示）    │  │ 订单系统 / orders-api  │
│ 集群 → namespace → Deployment │  │ 代码 → 镜像 → 容器     │
│ 容器与当前镜像                │  │ 测试环境 / 当前目标    │
│ 检查结果与可修复原因          │  │ 尚未保存 / 无发布动作  │
└──────────────────────────────┘  └────────────────────────┘
上一步                                           下一步
```

桌面主栏/摘要约 2:1，摘要是文字关系图而不是强制拖拽画布；窄屏按主配置、核对关系顺序叠放。
级联选择改变上游时清空依赖的下游值，明确重新检查；异步加载、无资源、无权限、连接失败分别解释。
保存前完整显示“组件—镜像仓库—环境—集群—namespace—Deployment—容器”，不要求用户从 ID 猜名字。
第二步在容器和镜像仓库选择后持续显示简短关系路径：`APP_NAME + TARGET_CLUSTER → 镜像仓库 → 集群/namespace/Deployment/容器`。窄屏纵向串联，桌面横向串联；tag/digest 标记为构建事件提供，旁边说明预览不会保存或改变集群。完整确认页保留全部字段，不能用路径图代替保存前复核。

策略选择使用三张等高选项卡：滚动、蓝绿、金丝雀，各给一句结果说明、条件与影响；选中后展示共享的发布路径图，计划预览复用同一图例。
不支持的选项可读取原因和“配置 Service / 连接网关”入口；不做空白灰卡或虚假可用开关。
蓝绿显示候选不接生产流量、切换方式与双份容量；接入预检将 Service、HPA、ResourceQuota 拆成状态卡，容量卡说明配额计算结果与调度能力边界；金丝雀显示权重能力和指标接入状况。
金丝雀阈值表单把六项值分为“样本与新鲜度、错误率、延迟”三组，统一右侧单位和辅助说明，不将原始小数暴露给用户；请求数、观测年龄和阶段观察秒数必须为整数，错误率上限用百分比、错误率增幅用百分点、窗口用秒、延迟用毫秒、相对延迟增幅用百分比。另用阶段卡片填写候选流量比例与最短观察秒数，首次选择时显示两张空白卡，明确引导 2–10 个递增阶段并以 100% 收尾，不预设生产放量比例。阈值或阶段未完整有效前，保存操作保持禁用，并在固定底部操作区说明当前必填项；长表单只滚动正文，标题与操作区保持可见。配置卡上方持续显示“等待网关联调 / 保存不改变流量”的清楚说明。不要把六个阈值字段挤成三列小表单，也不要用绿色开关暗示金丝雀已可执行。
首次接管的标签/selector 变更在核对区突出，技术详情折叠，不能把它藏进 YAML。

发布路径图要直接说明资源关系：滚动更新现有 Deployment；蓝绿准备隔离候选 Deployment，检查后切换既有 Service selector；金丝雀从既有网关入口分发到稳定/候选 Service，并按阶段调整权重。图示仅解释计划模型，始终附“未代表目标已接入或检查”的说明；真实能力状态另由预检和服务端计划返回。

## 5. 环境总览与发布计划

环境总览按测试 → 预发 → 生产展示同一组件，不把集群卡片伪装成环境。每个目标有自己的当前
版本、活动 Deployment、最新任务和观察时间；多目标环境先展示摘要，再展开各目标结果。
未知数据显示“无法确认”及原因，不以绿色徽标或空版本代表正常。制品验证与部署状态分开呈现；业务验证和安全扫描只在报告 digest 与目标当前镜像 digest 完全一致、且报告未过期时显示通过，失败、过期、缺少报告、读取错误和不可变 tag 均有各自状态。
组件绑定表以紧凑的二级信息展示活动 Deployment 名与短 UID；活动资源已从初始模板切换时，保留初始
资源名/UID作对照。UID 未知时明确显示“首次计划时确认”，不显示空白或假定已固定。
UID 冲突时，operator/admin 可从绑定行发起重新核对。确认弹层完整展示业务应用、集群、namespace 和
Deployment，并用短提示说明只读 Kubernetes、不切 Service 流量、保留模板及发布占用时拒绝；成功只更新
平台活动 UID。该恢复动作应紧邻资源身份信息，避免把身份修复误认为普通关系编辑。

计划页采用专页，顶部显示应用/组件/环境，当前与候选并列；中部给策略阶段、验证和恢复摘要；
底部显示阻断原因与主行动。审批人无需展开技术面板即可理解变更影响。

当前交付“计划预览”弹层与发布计划记录卡：用构建制品 → 目标组件/环境的关系布局，随后显示
发布旅程、已固定的 Deployment UID/resourceVersion、当前镜像、配置摘要和策略专属阻断原因；计划
可以从记录卡重新打开，审批行可直接查看申请绑定的只读计划快照。计划明确标注“只读预览，不会变更集群”。滚动策略可在核对快照后提交独立审批；
蓝绿显示候选准备、待切流、待业务验证、核对与恢复等真实运行关口；金丝雀显示未开放原因，发布中心不提供旧滚动入口作为旁路。这不等同于 UX3 的专页、
审批详情、完整运行现场或响应式/深色验收。

```text
订单系统 / orders-api                      生产环境
申请发布                          当前版本 → 候选版本
                                  构建、提交、digest 摘要

发布方式：蓝绿       验证：通过       恢复：保留旧版 〔计划值〕
准备候选 → 业务检查 → 人工确认 → 切换入口 → 观察 → 完成

目标与入口              验证依据             恢复条件
资源名称 + 环境          新鲜度/来源           旧版健康 + 兼容性
〔展开资源影响〕          〔查看报告〕           〔查看详情〕

申请后的计划不可修改；目标变化需要重新申请。         提交审批
```

“通过”只用于确有证据的事实，线框中的数值取真实计划，不提供虚构 KPI。
表单在请求失败时保留；审批过期/基线变化在原位置解释并提供重新预览，不弹一句失败就结束。
按钮提交中锁定重复点击，未知结果先查询任务，不能诱导再次发布。生产环境名称与提醒显眼，但
不让整个页面变成红色警告；只有破坏性或失败信息使用危险色。

## 6. 发布现场：进度可信，行动明确

页面顶部固定组件/环境、当前状态、开始时间、最近观察和任务 ID；主体左侧阶段时间线，右侧
显示版本/流量/业务检查。下方“事件 / 资源 / 日志”分页，默认事件。日志不作为首页主视觉。
时间线区分完成、当前、待执行、等待确认、失败和未知，有文字与图标，不能只用一条百分比进度条。

| 场景 | 主要展示与动作 |
|---|---|
| 部署候选 | 就绪副本、当前镜像、检查中；阶段内指标不伪造业务通过 |
| 蓝绿待确认 | 稳定入口/候选预览、检查依据；主行动“确认切换” |
| 金丝雀观测 | 阶段权重、已生效配置、实际请求占比、窗口与样本；主行动按权限“确认下一阶段” |
| 暂停 | 显示实际流量去向：切流前仍由稳定版本承接，切流后仍由候选版本承接；暂停只停止平台推进，继续后仍需人工确认 |
| 写入结果未知 | 最近已知状态与观察时间；“核对状态”，禁止继续扩大和盲目重试 |
| 指标缺失/过期 | 缺什么、截止时间与处理入口；无数据不是通过 |
| 恢复中 | 正在恢复的目标、入口确认、业务检查，成功前不显示已恢复 |
| 成功但清理失败 | 发布成功与残留资源告警同时展示，给管理员清理入口 |

流量图使用一条稳定/候选对比条，颜色仅识别版本，健康另用状态文字。蓝绿只呈现入口切换，
不展示不存在的 20% 流量控制；金丝雀同时列“计划 20% / 已生效 20% / 实际请求 17%（窗口、样本）”，
数字为示意，线上从真实数据生成。观测未知时保留最近值加过期标记，或显示未知，不能填 0。
不以跳动动画营造监控实时性；页面显示观察时间，前端刷新时间不等于网关或指标更新时间。

暂停、取消和恢复分开。蓝绿暂停只停在当前人工关口且保留资源锁；取消先确认稳定 Service 入口恢复，再结束运行并保留候选。切流后的取消说明需要恢复；恢复确认专门核对目标、稳定容量、兼容性和
可能残留连接。按钮文案不叫含糊的“一键回滚”。按钮可见性/禁用原因以服务端可用动作决定。

## 7. 状态、可访问性与响应式

- 按钮、输入和策略卡覆盖默认、悬停、焦点、激活、禁用、加载状态；禁用操作旁有可读原因。
- 首屏加载用与布局一致的 skeleton；刷新保留已知数据与加载标记，不闪成空白。
- 空页面给一句原因与一个主行动；无权限给所需角色，接口失败给具体原因与重试入口。
- 表单字段就地报错并关联 aria-describedby，提交失败将焦点移到错误摘要；弹层管理焦点与关闭后归还。
- 键盘可走完整接入/审批/恢复，焦点可见。状态播报不反复打断输入；颜色、tooltip 不能独占含义。
- 桌面按钮高度通常 36/40px，移动触控目标至少 44px；危险动作之间保留足够间隔。
- 1440/1280px 使用双栏；1024px 收敛摘要或改为单栏；390px 单栏、底部行动不遮挡内容。
  表格按列优先级折叠成行摘要，必须的完整数据可横向滚动，不挤成无法阅读的多行窄列。
- 长中文名、长镜像地址、64 位 digest、几十条事件、200% 缩放和深色主题均不溢出或丢操作。
- 时间保存/API 使用 UTC，界面明确本地时区与相对时间；详情可看绝对时间。过期阈值由观察策略给出。
- 过渡通常 150–200ms，遵守 reduced-motion；不对关键状态持续闪烁，不新增重量级动画依赖。
